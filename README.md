# Stage Relay 0.1.0 · 多 Agent 协作台（Codex + DSH）

由你指定成员和职责，面板把工作交给原应用中的真实 Agent 执行。Codex 与 DSH 的原生任务组协作已实际验证；面板不直接调用模型 API，也不替 Agent 决定结论。

这是 0.1.0 全新版本线：仓库主线的旧版（1.4.0 系列的「模型阶段接力」插件）已保留为独立分支，与当前结构不兼容，不在此目录内。

## 能力概览

- **项目与分工**：一个任务指定方案监督、执行、汇总负责人；可添加同应用多个成员，也允许一人兼任多职责。
- **项目级群聊**：每个任务一条群聊线程，没有议题也能交接。消息进入其他成员信箱，成员需主动读取才能响应；成员连续发言 4 条后等待用户回复。
- **原生会话绑定**：登记来源（面板创建 / 用户绑定）、会话 ID 与绑定轮次。成员卡固定显示「绑定会话 + 轮次 + 忙碌状态」，明确它不是你可能正在看的那个窗口。
- **结束与清理**：结束任务与「已生成汇总」是两件事；结束时停止派发、撤销未完成板块、按来源归档或解绑会话，并提供固定规则的清理预览与可恢复移动。
- **设置与占用**：按项目显示本应用登记的附件、临时目录与可恢复区容量，提供清理预览与恢复入口；工作区不计入、不扫描。
- **项目回收区**：项目可「移入回收区」并逐条「移回列表」，工作区文件始终不动。

## 从源码启动

需要 Python 3.11 或更新版本，无需第三方依赖。

双击根目录的 **启动 Stage Relay.cmd**，或运行：

```powershell
python app.py --open
```

默认地址为 [本地面板](http://127.0.0.1:4318)。数据保存在根目录的 `data/`，只监听本机；重复运行会复用已启动的服务。

## 打包 Windows 桌面版

```powershell
python build_desktop.py
```

输出到 `release/StageRelay-<版本>-codex-dsh/`，生成带独立窗口的 `Stage Relay.exe`、协作桥 `StageRelayBridge.exe` 和随附运行环境，目标机器不需要安装 Python。桌面窗口使用 Microsoft WebView2 Runtime。`release/`、`build/` 与本机 `data/` 都不入库。

## 建立自己的任务

1. 新建任务，填写目标，选择或新建工作区文件夹，再指定方案监督、执行、汇总负责人。
2. 添加工作板块，指定负责人并填写验收条件，然后派发。
3. 在成员卡把原应用会话绑定到该职责；成员自己读取信箱、执行并汇报。
4. 执行结果由监督者独立核验；核验通过后再派发汇总。
5. 任务完成后「结束任务」；需要从列表移除时再「移入回收区」，随时可移回。

## 结束任务与清理的边界

结束按钮先二次确认并填写保留期（1-365 天），然后：

1. 置为只读，停止派发，把未完成的板块标为「已撤销」，取消尚未送达的原生任务。
2. 只处理登记过的资源：面板创建的会话请求原应用 `workspaceRegistry.archiveSession(sessionId,{stopActivity:true})` 归档；用户手动绑定的会话只解除绑定。
3. 共享应用、插件、接入配置与工作区一律保留，不按进程名关闭进程，不删除原应用数据库。
4. 清理只按固定规则列候选（本应用为此项目创建的 `tmp/<project_id>`、已无引用且超保留期的上传附件、已删除项目的孤儿附件与过期计划）。执行时移入 `recovery/` 并写 `manifest.json`，原子落盘、可恢复；失败项保留原位，重复运行不扩大范围。

## 如实说明的限制

- 插件侧的归档调用已实现，但当前安装的 DSH 版本是否向插件暴露 `workspaceRegistry` 尚未做端到端验证；未暴露时回执失败并保留待重试，不会静默当作已归档。
- DSH 插件接口不提供原生子会话的父子关系，因此只登记面板实际创建的会话；原生 `turnId` 也无法取得，执行记录显示为未知，只用 jobId / 事件序号 / 绑定轮次关联。
- Antigravity 尚不支持原生唤醒。

## 检查与证据

```powershell
python -m unittest discover -s tests -q
node --check web/app.js
python qa/ui_fixture.py && node qa/ui_probe.mjs
```

`qa/` 下另有端到端脚本：`recycle_e2e_check.py`（项目回收往返）、`release_038_check.py`（打包 exe 清理流程）、`ab_dispatch_verify.py`（双会话派发隔离）、`rework_verify.py`（清理计划并发）。它们各自使用隔离数据目录与独立端口，不触碰真实项目。
