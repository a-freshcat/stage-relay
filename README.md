# Stage Relay v1.0.0 · 模型阶段接力

<img src="assets/icon.svg" alt="Stage Relay" width="80" height="80">

[下载 1.0.0](https://github.com/a-freshcat/stage-relay/releases/tag/v1.0.0) · [更新记录](CHANGELOG.md)

用于 Codex 的本地协作插件：复用当前对话的方案，让其他 Responses 兼容模型执行，再由用户确认、当前 Codex 或已有模型审核。面板展示任务、执行回答、审核结论和问题处理路径。

首次安装需准备 Python 3.11+、Git 和可用的 Codex CLI。从 GitHub Release 下载 `stage-relay-v1.0.0-plugin.zip`，解压后将 `config.example.json` 复制为 `config.local.json`，再按下文生成本机接入配置。压缩包中的 `.mcp.json` 是空的初始化模板，不能直接充当已配置服务；接口和密钥在自己的电脑上设置。真实模型生成与审核按供应商规则计费，打开面板不发起生成请求。

在对话里说明任务并调用插件后，Codex 直接准备方案，将原始任务带入面板；已有面板会自动读取新方案，不再要求用户重新输入、复制回对话或手动读取安排。确认页中的补充用于新增和调整要求，会随原始任务和方案一起发送；冲突细节以本次补充为准。新任务会清除上个任务的补充，同一任务的方案更新会保留尚未提交的补充。“暂不执行”由保存草稿、不提交任务来落实，不作为执行端的禁止执行约束。

面板任务执行后可点击“我已确认，结束任务”，或点击“选择审核方式”：复制请求给当前 Codex 对话，或从已经保存的接口和模型中选择审核模型。接口与密钥直接复用，不要求新增配置；读取选择列表不请求模型。点击“用所选模型审核”才发起可能计费的审核，只检查保存的结果与证据，不重新执行任务或重跑测试。同一模型、接口和结果已有有效审核时直接复用。用户确认与模型审核分别保存，结果变化后失效；不会改变测试的实际通过或失败记录。高级 CLI 或显式 auto 配置仍可使用原规划模型自动审核。

结果栏直接显示“执行模型的回答”和“审核结论”，注明实际审核模型和接口名称。旧记录用已保存的完成说明回显，不伪造新回答。网页无法自行唤醒 Codex 对话，选择 Codex 时需将复制的请求发到对话。审核记录绑定当时的结果与测试证据，结果变化后显示失效；不会自动重跑旧任务或启动循环修复。选择其他审核模型不改变原任务的规划、执行配置。

“检查所选模型”分为“查看模型列表”（无生成请求）、“试着回答一句”和“试跑接力格式”（各有一次真实模型请求，可能收费），按钮下分别说明范围。这些测试用于检查接口调用，与项目代码的测试不同。任务未配置项目测试时作为中性说明，不重复计入问题；回复类任务可对照目标、回答与规划端审核确认。问题旁的“查看说明与处理方法”给出具体解释，并可跳转执行记录或测试与代码差异。项目测试命令配置见下文的 checks 示例。

问题有处理和结束路径：原规划端逐条说明检查对象、核对方法、预期结果；核对后将已解决或确认与本次无关的 residual 索引记录在审核的 resolved_residual 中，同时保存依据。该条随后移到结果栏“已核对的提醒”，不再计入问题数；旧原话和核对依据仍可查看。未解决的条目保留，失效审核不会继续关闭问题，失败测试不会被手工标成通过。当前 Codex 模式可从问题旁直接复制核对请求回到原对话。

当前 Codex 模式显示“给当前 Codex 的任务指示”和“补充执行要求”。已有方案会带回任务文字；补充要求加入本次执行的约束，不覆盖原方案、不另起规划模型。新任务可复制到当前对话准备方案；任务或项目变化时禁止使用旧方案执行。网页本身不能自动唤醒当前对话。

调用方使用 `relay_prepare` 时可附带 `user_request`（本对话的原始任务）和 `instructions`（已确认的用户要求）。面板只读取随方案保存的本地指示，不扫描其他对话；已确认要求会并入执行约束。打开后自动回显原始任务，并提示“确认时还想调整什么？”。旧方案未保存原始任务时明确标为“已保存的任务摘要”，不会伪装成完整对话记录。原始任务用于回显，执行仍复用已准备的方案，避免再发送整段聊天历史。

运行中约 1.5 秒读取进度，空闲约 10 秒，页面切到后台后暂停，返回时立即读取。JSON 格式修复只发送契约、错误和上一份报告，原任务上下文保留在本地供按需读取，避免重复发送整份方案。模型输出长度、工具及原有修复配置保持不变。生成的快速打开脚本随版本更新，用户自行改写的脚本保留。

界面使用深色顶栏、蓝色任务区、暖色补充区、独立方案区和执行设置区，并拉开标题、正文和辅助说明的字号与字重；错误同时带红色和文字标签，主要操作使用更醒目的按钮。

独立检查在 HTTP 200 后发生 Codex 进程错误时，会标为“运行模型进程”，不会当作上游 HTTP 拒绝。失败检查的进程输出、请求元数据和退出结果会脱敏保留在运行目录 `.check-diagnostics/`，面板提供本地诊断位置；临时样例仍会清理。请求计数来自实际转发记录，本地初始化失败不会记为一次模型调用。

项目提交失败时，面板会说明目录不存在、Git 仓库不可访问、没有首次提交、选择了子目录或已有未提交改动等具体原因。项目目录应为实际存在、已提交且干净的 Git 仓库根目录；`.test-tmp` 属于自动清理的开发测试目录，不能作为长期项目使用。

普通用户现在直接填写 **API 地址 + API Key**。密码框默认遮挡密钥；读取模型目录使用刚填的 Key，保存配置时交给 Windows 凭据管理器，JSON 和任务快照仅保存引用。重开面板无需重新填写，实际执行也读取同一保存的密钥。不需要 PowerShell 或设置环境变量。“此接口无需密钥”和“高级：使用环境变量”可单独选择。支持替换、移除保存的密钥；移除或替换后仍引用旧密钥的历史任务可能需要重新配置凭据。

“模型与接口”按配置顺序操作：先填写 API 地址和凭据引用，点击“读取 API 模型”，直接从尚未保存的接口获取目录；勾选所需模型并加入本次配置，再为两个角色选择模型、保存配置。角色列表只包含已选模型，不会把整个接口目录都保存下来。可搜索模型，点已选项旁的 × 删除模型，也可删除整个接口；删除后需重新分配受影响的角色，保存并重新打开后不会恢复已删除项。关闭重开可放弃未保存的编辑。

目录请求由本地服务发送，使用刚填写或已保存的密钥，服务端不会把保存的密钥返回网页。不进行定时模型探测或生成请求。目录只反映接口声明，不代表逐一通过生成、Responses 或工具调用测试。未提供目录、认证失败、服务未启动等情况显示原因；手动添加仅作为目录不可用时的备用方式。

调用 `@stage-relay` 时，先唤起协作面板。打开、查看与修改接口配置不会调用模型；在面板中填写项目目录和任务，点击“开始任务”后才运行。可选“完整接力 · 规划 → 执行”，或“已有方案 → 执行”以复用规划。两栏显示各角色公开输出，下方显示实际交接包和本地验收结果。模型仍按阶段接力。

插件新增 `relay_open_panel`：返回本地 URL，由调用方在浏览器侧栏打开；不支持内嵌浏览器的客户端可传 `open_browser=true`。面板进程会复用。更新插件后，旧会话如仍只有三个工具，需重新连接插件；技能内含旧会话的本地启动回退。

## 作为节省上下文的本地插件

支持调用方 agent 提供已有方案，直接交给配置好的执行模型。在这一模式中不额外启动 Sol 规划；设计决策受阻时，将问题交回调用方。双阶段 CLI 和面板的完整接力模式使用配置的规划模型。

先生成本机接入配置（只写插件目录内的 `.mcp.json`，不调用模型、不改客户端设置）：

```powershell
cd "C:\work\stage-relay"
Copy-Item config.example.json config.local.json
python configure_plugin.py --config "config.local.json" --projects-root "C:\work\projects"
```

将命令中的路径替换为自己的插件目录和已经存在的项目上级目录。已有 `config.local.json` 时保留它，不再执行复制。配置执行入口与验收命令后，在支持本地插件的客户端中导入本目录；或把 `.mcp.json` 中的 `stage-relay` 项注册为 stdio MCP 服务，两种方式任选一种。移动目录后需重新生成本机接入配置。插件目录本身应可写，用于本地日志和项目锁。

工具包括 `relay_open_panel` 打开协作界面、`relay_submit` 提交已有方案、`relay_wait` 本地等待并取结果、`relay_resume` 显式恢复或交回修订方案。说明及调用示例见 [插件接入](skills/stage-relay/references/setup.md)。该版本是本地 stdio 插件，尚未发布到公开市场，也不提供远程网页接入。

节省消耗的方式：

- 复用调用方已有方案，传递完整的必要事实；不再额外设置 12 KB 的交接预算。
- 同一项目及 task_key 重复提交相同方案，会返回原任务；方案不同则拒绝，避免网络重试重复付费。
- 执行请求次数、修复轮次、输入/结果大小与超时直接继承原配置，不再附加较小限额。原配置未设置 `worker.max_output_tokens` 时，插件不注入输出上限；明确配置了才沿用。
- 保留已配置的插件、MCP 工具、项目规则及原审批设置，不用禁用能力来减少上下文。
- 等待、面板和状态判断由本地代码完成。成功结果只预览文件改动，未解决问题、验收结论和阻塞证据保留完整内容；`relay_wait` 的 `full_result=true` 可取回完整结果，不重跑模型。预览省略内容会明确标记。传入 revision 可避免重复返回相同内容。
- 复用方案模式不额外启动规划模型，设计阻塞交回调用方；完整接力模式使用配置的规划角色。不阻止执行 CLI 正常压缩上下文。模型必要的思考、代码输出和修复机会不作为省 token 的削减对象。

旧版未完成任务在显式 `relay_resume` 时会备份原快照，并从其来源配置（旧元数据无来源时使用服务当前配置）恢复被插件压低的限额；累计请求数不清零，模型、接口、验收命令及项目基线不变。运行中任务和已完成历史记录不自动修改。新任务使用带版本标记的原配置快照恢复。

原有运行安全约束仍在：配置中的次数、超时、日志/文件大小，Git 基线、路径和结构校验，以及 2 MB MCP 单条消息保护。它们可能显式停止任务，不能把“没有插件额外压低限额”理解为无限制。检查反馈保留原日志尾部并附完整日志路径，模型可按需阅读。

这些措施减少重复工作，**不保证所有任务都比直接执行省钱**。技能说明、工具定义、工具返回仍占调用方上下文；CLI 请求还包含自身指令与工具定义，实测本地假接口首请求约 26 万字节。字节不等于 token。缓存 token 属于输入的一部分；报告缺失用量和费用时保留未知。额外审批/供应商内部请求未必经过此请求门，不能据此宣称全账号硬限额。

插件任务默认保存在 `runs/plugin/<job_id>/relay`；观察时使用 `python panel.py --runs-root "runs/plugin" --open`。面板会注明“调用方 agent · 复用已有方案”，并展示真实交接。当前直连入口若使用环境变量凭据，需让启动 MCP 的客户端进程继承该变量；在另一个 PowerShell 临时输入过密钥并不自动满足这一点。

Sol 读取相关代码并产出计划 → 退出 → DeepSeek 独立实现与测试。普通问题由 DeepSeek 限次修复，只有具体设计决策阻塞才限次回到 Sol。调度、等待与状态保存由 Python 脚本完成。

Windows 10/11 + Python 3.11+ + Git + Codex CLI，无第三方 Python 包。当前开发验证环境为 Windows、Python 3.14、Codex CLI 0.163.0-alpha.10.2。DeepSeek 通过 CCSwitch 的 Responses 兼容入口接入；第一版无需另启 DSH 客户端。

## 查看两个角色的输出与交接

```powershell
python "C:\work\stage-relay\panel.py" --open
```

两栏显示 Sol 的规划和 DeepSeek 的执行，可切换阶段、展开实际输入与结构化结果。交接时间线直接提取接收阶段 `input.txt` 中的计划、上轮结果及检查反馈；保留失败与重试记录，显示独立检查和最终代码差异。

面板每 1.5 秒读本地文件，**打开、查看、刷新和保存接口配置都不启动 agent 或调用模型**。只有点击“开始任务”才启动所选工作流并产生供应商用量。所有页面资源都在本地，无额外模型摘要。请求配额及模型提示保持原设置；两个角色的模型工作仍按阶段执行。开发此功能本身会消耗开发对话的 token。

通过插件打开的面板可启动任务；手工运行时增加 `--projects-root "<允许的项目上级目录>" --runs-root "runs/plugin"` 才启用开始按钮。不指定允许目录时仍可查看日志、修改接口。目标须为已提交且干净的 Git 项目，运行记录须位于目标仓库外。同一页面相同任务重复提交会复用记录。

点击右上角“模型与接口”，分别为规划和执行选择入口并填写准确的模型 ID，不限定 GPT 品牌。展开“新增或编辑接口”可维护常用入口及模型列表：

- 现有 CCSwitch / Codex 供应商：填写 `~/.codex/config.toml` 内已存在的供应商 ID，例如 `custom`；本机原生登录透传可沿用当前设置。
- 自定义 Responses 兼容入口：填写基础地址及 API Key。保存的密钥由当前 Windows 用户的凭据管理器保管；留空保持已有密钥，粘贴新 Key 可替换。高级用户仍可选择环境变量方式。

先将新增入口加入候选列表，选择角色后点击“保存配置”。候选入口保存到配置文件同目录的 `providers.local.json`，角色选择写入 `config.local.json`。运行新任务时用 `relay.py run --config "<该配置文件>" ...`；可展开设置内的“如何用于新任务”查看实际路径。面板参数 `--config "<其他配置文件>"` 可指定要编辑的文件。正在运行的任务、历史运行副本及全局 Codex / CCSwitch 配置不被修改。

当前执行器要求 Responses 协议。只有 Chat Completions / Anthropic Messages 原生协议的接口，需要经 CCSwitch 等适配层转换；保存配置不代表已验证供应商、认证、工具调用或模型身份，不进行自动付费探测。兼容要求参见 [OpenAI 官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

默认发现 `stage-relay/runs` 下的记录，运行新任务后自动更新任务列表。也可用 `--run-dir "<relay产物目录>"` 观察外部项目的指定任务；`--port 0` 自动选择空闲端口。服务只监听 `127.0.0.1`，终端打印带随机路径的本地地址；Ctrl+C 关闭面板服务，已在另一终端运行的任务继续执行。

这里显示已保存的公开消息和工具事件，包含最近有限长度的日志；没有隐藏推理或逐 token 动画。历史日志没有逐条时间戳，时间线按阶段编号和事件顺序排列。界面的“运行中”来自检查点文件，不保证进程仍存活；客户端或机器意外退出后可能保留旧状态。输入与请求 token 来自 CLI 报告，输入包含缓存部分，完整费用未知时仍显示未知。

## 接入真实模型

`config.example.json` 中的 `gpt-6.1-sol` 与 `ccs-deepseek/deepseek-flash` 是示例模型 ID，`custom` 是示例已有供应商名称。请在面板使用自己接口返回的准确 ID，保存需要的模型，并确认供应商路由；请求里的名称不能证明实际上游的模型身份。若配置了模型目录，preflight 会先校验角色模型在目录中。

两个角色的 `endpoint.codex_provider` 都指向现有 `~/.codex/config.toml` 的 `model_providers.custom`。脚本只读取选中的 provider，密钥仅在内存用于转发；不写回 Codex/CCSwitch 配置、不读取数据库中的密钥，不接受把密钥放入本工具 JSON 配置。也支持固定 Responses 地址：

```json
{"base_url":"https://your-responses-gateway.example/v1","api_key_env":"YOUR_GATEWAY_KEY"}
```

**本机当前 CCSwitch 默认通道是 Codex 官方登录**：使用 `config.ccswitch-native.example.json`，或演示时加 `--native-auth`。此模式让原生 CLI 自行取得原有认证并仅透传到用户自己的 loopback CCSwitch；调度脚本不读取或改写 `auth.json`，也不存储认证头。临时 gate 通过随机私有路径识别本阶段请求。仅使用第三方 API-key 入口时可用普通配置；原生登录透传禁止指向远程地址。

先在 CCSwitch 中启用当前需要的本地聚合/路由；进程启动不等于服务正在监听。`preflight` 只探测 TCP，不消耗模型额度，也不证明认证、模型或协议可用。

可先生成一个独立演示仓库：

```powershell
python demo.py --prepare-only --native-auth
```

它会输出 `project/config/request/run_dir` 的实际路径。用这些路径执行：

```powershell
python relay.py preflight --config "<config>" --project "<project>"
python relay.py run --config "<config>" --project "<project>" --request "<request>" --run-dir "<run_dir>"
```

或者 `python demo.py --live --native-auth` 新建一次真实模型演示。**`--live` 会产生 API 用量**：演示现在继承样例配置中的执行设置，不再额外压低请求次数、任务超时或修复轮次。当前样例为规划最多 30 次、执行最多 80 次累计请求，不代表固定美元上限；保留原有审批服务可能另有用量。默认不带 `--live` 时仍只用本地假模型。

接入自己的项目时，复制配置为 `config.local.json`，填写 `checks` 的 ID → 参数数组，例如：

```json
{"unit":["python","-m","unittest","discover","-s","tests"]}
```

检查程序直接启动，不隐式使用 shell。Windows 的 `.cmd` 命令需要用户在配置中显式选择对应解释器或实际可执行文件。计划只能引用配置中的检查 ID；模型生成的命令不会进入调度器执行白名单。没有配置检查时，结果为 `needs_manual_verification`，不会宣称验证通过。

## 已落实的边界

- **串行**：在当前用户临时目录按项目路径建立 OS 文件锁，不依赖插件安装目录可写；不同插件版本和任务共享这把锁，不自动并发修改。
- **可恢复基线**：目标必须是有提交且无现有改动的 Git 仓库根目录。run-dir 必须放在目标仓库之外。不会自动 stash、提交、reset 或删除你的代码。
- **厚交接**：计划包含 codeFacts、具名决策/步骤、范围与验收 ID；本地另存引用文件哈希。传递实施依据，不要求隐藏思维过程。
- **严格升级**：`needs_replan` 必须引用已有 `failedStep` 和 `decisionNeeded`，并包含尝试、原因与证据。缺失字段是协议故障，不自动升级。
- **故障分开**：认证、网络、进程错误、无效 JSON、超时不会自动回到高配。测试失败按 `max_fix_rounds` 回到普通模型，设计纠偏按 `max_replans` 限次。
- **调用前限次**：CLI 的每个主模型 HTTP 请求经临时 loopback gate，检查模型标识、请求大小并在转发前持久化计数。planner/worker 的配额按整个任务累计，不在重试或恢复时清零。API-key 模式只把本阶段随机凭证交给子进程，真实上游密钥留在转发层；原生登录模式由 CLI 自行管理既有登录。
- **时间/日志限制**：超时或日志超限终止阶段进程树；Windows 使用 Job Object，也清理阶段启动的后台子进程。
- **保留安全设置**：不关闭审批、不覆盖 approval_policy/approvals_reviewer、不使用 bypass 参数。规划使用只读、执行使用 workspace-write；仍可能因权限或审批而停止，需要正常处理该请求。

这些是调度与账目约束，不是隔离不可信代码的新沙箱。OS 锁只协调本工具；外部编辑仍可能发生。`expectedScope` 是模型应遵守的范围，workspace-write 不是逐文件写入白名单；Git diff 供复核。不要让同一项目同时运行其他修改任务。

## 恢复

执行接口和模型可在任务区直接选择；模型下拉框读取所选接口的完整目录，区分接口返回数量与已保存数量。应用或开始任务时，只保存选中的执行模型，不更改规划端。目录声明不代表生成或工具调用已经通过验证。密钥显示“已保存·本机可读取”或“不可读取”，不会回填到密码框；留空保存保留原密钥。

一轮任务结束后，可在原输入上点击“再次运行”启动新一轮；运行中按钮禁用，传输状态未确认时保留原提交键以避免误重复。新一轮仍要求干净项目，不自动撤销上轮代码改动。

Windows 面板应从正常用户进程启动。若从宿主的受限执行环境启动，真实 Codex CLI 可能在初始化 app-server 时被拒绝访问，尚未到达模型接口。正常启动面板可让模型进程继续使用原有 `read-only` / `workspace-write` 沙箱及审批设置，无需关闭保护或搬动用户 Codex 配置。新版将此问题单独报告为 `cli_initialization_error`。

面板默认使用“当前 Codex 方案 → 执行”。在当前对话提出任务，调用方用 `relay_prepare` 保存本地草稿；面板读取并展示方案，用户点击开始后只调用执行模型。准备、查看与删除记录均不调用模型。网页不能自动唤醒当前对话，新任务需先在对话中交代。`relay_submit` 仍适用于已授权直接执行的方案；API 规划模式可手动选择。

任务记录支持单条删除，也可展开“选择多条任务记录”，勾选或全选后批量删除；“撤销上次删除”一次恢复整批记录。删除只从列表移除，保留本地日志、检查点和防重复提交信息，避免重复提交产生额外调用；项目文件不变。运行中或排队中的任务不可选；提交删除时再次核对，状态变化则整批保留并提示刷新。上游明确拒绝时，面板区分账号无模型权限、出口 IP/地区限制、认证失败、限流和其他接口错误，仅保存分类与 HTTP 状态，不保存上游错误原文。

任务记录以用户原始任务为标题。新规划和执行阶段要求使用任务所用语言（保留 JSON 字段名、枚举、文件路径和代码标识）；历史输出保留原文，不额外调用模型翻译。

0.8.x 起，任务页首屏固定为“目标 / 结果 / 问题”三栏，均由已保存记录在浏览器内生成，不增加模型调用、不截断或删除原始交接内容：

- 目标使用用户任务；结果说明执行端报告了什么、独立检查是否通过；问题集中显示失败、受阻、检查未通过、待人工验证、未完成检查与遗留事项。失败和阻塞标红并带文字标签，待人工验证或未完成检查标黄。
- 字段含义分开：完成的结果不显示笼统“原因”；`needs_replan` 才显示“调整原因”，`blocked` 才显示“阻塞原因”，`decisions[].why` 标为“决策依据”，缺失就不显示，不用其他字段补位。
- 交接记录默认折叠，每条只显示“谁交给谁、当前状态、交接目的”；步骤、代码事实、完整输入和原始 JSON 移入详情。步骤多于 6 项时显示数量，展开再查看。
- 运行中显示当前阶段和最近一条公开事件；完成后首屏是结果与问题，两栏输出、交接、检查与代码差异保留在“历史过程”折叠区。
- “执行端报告完成”和“独立检查通过”是两个独立结论；没有配置检查时显示“待人工验证”，不会把自报完成当作验证通过。

即使任务在创建阶段记录前失败，也会保留在列表中。新版失败记录包含阶段、角色、接口或本地位置、异常类型、系统错误码、处理建议和日志路径；不保存异常原文、认证头或密钥。旧版只保存 `local_error` 的记录不能自动还原完整原因。

## 快速打开面板（0.9.0）

- `relay_open_panel` 与本地快捷方式都走 `relaylib/panel_runtime.py`：先读 `.panel.json`，只有配置、项目和版本组成的 identity 一致、且该实例的 `api/health` 仍应答时才复用现有 URL。
- 本机实测：复用约 9–35 ms（读记录 0.2 ms，健康检查 0.9–15 ms，主要是回环连接）；冷启动约 0.3 秒，其中进程启动约 8 ms、面板就绪约 310 ms。复用路径不再创建 urllib 代理 opener（此前每次约 20 ms）。
- 每次打开把各阶段耗时追加到运行目录的 `.panel-runtime.json`，便于比较，不影响任何模型限额。
- 健康检查超时从 1 秒降到 0.75 秒；记录失效（实例不匹配、端口已关闭）时才重新启动面板，不等待超时。
- 若现有面板健康但版本与当前插件不同，**仍然复用它**（避免两个版本反复启动服务），并在返回值与面板顶部提示“重新连接插件”；不会因版本不同就再起一个服务。
- 本机会生成 `runs/plugin/打开面板.cmd`：双击即可启动或复用面板，不经过模型对话，也不注册开机自启。面板顶部会显示该快捷方式路径。
- 运行目录中的 `.panel-history.jsonl` 记录最近 20 个面板实例（有界、仅本地，同一实例只记一次）。若历史中仍有另一版本的面板在应答，`relay_open_panel` 会返回 `reconnect_required` 与提示，要求先重新连接插件，避免新旧版本并存。

## 检查所选模型（0.9.0）

“执行模型”下方新增三个独立按钮，只有点击才会执行；打开页面、刷新模型目录、开始任务都不会自动运行：

| 检查 | 实际动作 | 能证明什么 | 模型请求 |
| --- | --- | --- | --- |
| 接口与模型目录 | `GET /models`（不带缓存） | 网络、目录认证、所选模型是否在目录中 | 0 |
| 最小生成测试 | 真实 Codex 在临时回读样例中请求一次 | 所选模型当前能否返回非空回答 | 1（网关限 1 次） |
| 接力兼容测试 | 同上，并要求返回通过本地结果 Schema 的 JSON | 真实 Codex → 网关 → 模型 → 本地 JSON 校验可用 | 1（网关限 1 次） |

- 生成与兼容测试在系统临时目录新建只读样例仓库，结束后删除；不读取、不修改用户项目。测试前后比对样例指纹，若被修改则判为失败。
- 每次记录测试时间、模型、接口、失败阶段、真实 HTTP 状态、耗时和处理建议；检查记录写入运行目录的 `.model-checks.json`。
- 记录按配置 revision、接口、模型和凭据引用计算签名；接口、模型或凭据变化后标记为“记录已失效”，历史通过只说明当时成功。
- 不遍历全部模型、不自动重试、不切换模型，也不改变任务的请求次数、超时或修复轮次。网关对检查会话的限额固定为 1 次转发。

```powershell
python relay.py resume --run-dir "<run_dir>"
```

已完成且结果有效、项目指纹一致的阶段可直接恢复，不重复调用模型。阶段中断或失败可能留下部分修改：先看 `state.json`、阶段日志和 Git diff。确认可以重做后，用 `resume --retry-interrupted` 明确接管当前部分修改；已用请求配额仍保留。该参数不允许跨 Git HEAD 接管。

每阶段使用独立短上下文，不用 `codex exec resume` 传递整个历史，也不依赖 Codex 会话历史库恢复。V0.1 只支持 `planner.persist="handoff_only"`；不根据“纠偏两次”等未经验证的阈值推断缓存收益。进程存活、会话保存与供应商缓存是三个不同条件。

## 费用与尚未验证的部分

`budget.json` 记录本工具实际转发次数，`requests.jsonl` 只记录角色、请求模型、字节数与状态，不记录密钥或请求正文。CLI 中间输出另存于每阶段日志，可能包含项目代码，请留在本地。

usage 仅作事后观测，未知金额是 `null`，不当作免费。隐藏审批请求、网关内部重试和真实上游模型身份不能仅靠本工具日志确认。请求次数上限仅覆盖经过本 gate 的请求，不等于全账号或全供应商上限。

可选 `python audit_ccswitch.py --run-dir "<run_dir>"` 只读查询账本并按 CLI 线程 ID 关联，不读取供应商凭据。当前本机 CCSwitch 版本会给部分代理请求生成独立 session_id，不能保证与 CLI 线程 ID 对应；无匹配时输出 `no_matching_ledger_rows_cost_unknown` 和空金额，不用时间相近的其他对话冒充本任务账单。此时需要在 CCSwitch 中人工核对该次请求，尚不能自动提供完整费用总额。

**V0.1 不宣称美元硬上限**：配置非空 `budget.hard_cap_usd` 会拒绝启动。CLI 一阶段内可以多次推理；按外层阶段预扣无法覆盖内部请求。没有完整计数、可保证的 token 上界、输出上限和所有计价项时，不伪装成“严格预算”。需要真实硬限额时在网关/供应商实施并验证，然后另行适配。

审查文件中的历史费用与跨模型重算属于特定账本和反事实估算，不代表此工具已测得节省倍数。应按相同代码基线、相同验收条件比较“每次被接受改动的总成本”。

## 文件

`relay.py` 是入口；`relaylib/runner.py` 负责状态机；`gateway.py` 负责受限转发与调用前计数；`runtime.py` 负责检查点、进程树与 Git 指纹；`contracts.py` 定义结构与升级规则。计划/结果 Schema 在运行目录生成，便于第三方审查。

# 网关结构化输出兼容

Relay 将 JSON 输出契约放入提示词，不向 Codex 传入 `--output-schema`，因此网关无需支持 `text.format: json_schema`。收到输出后，Relay 本地校验 JSON 形状和交接语义。

JSON 语法或字段形状错误时，使用同一模型只读修复报告，不重新执行项目修改；修复次数沿用用户配置的 `limits.max_fix_rounds`，请求继续计入原角色累计记录。语义错误、接口错误和权限错误不会触发格式修复或自动换模型。上游拒绝请求时保留原 HTTP 状态码，只返回脱敏错误类别。
