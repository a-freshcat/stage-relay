# Stage Relay 1.4.0 · 模型阶段接力

<img src="assets/icon.svg" alt="Stage Relay" width="72" height="72">

[下载正式版](https://github.com/a-freshcat/stage-relay/releases/latest) · [更新记录](CHANGELOG.md) · [进阶配置](docs/advanced.md)

用于 Codex 的本地插件：让当前对话准备方案，交给你选择的模型执行，再由你确认、当前 Codex 或已保存的模型审核。面板展示任务、执行回答、审核结论、问题和交接记录。

## 安装与配置

需要 **Python 3.11+、Git、可用的 Codex CLI**，以及支持 OpenAI Responses 和工具调用的模型接口。可接 CCSwitch 等网关，不要求运行 DSH 客户端。

1. 从 Release 下载插件 ZIP 并解压。已有配置升级时保留 `config.local.json`、本机 `.mcp.json` 和运行记录。
2. 首次安装在插件目录运行以下命令，把项目路径换成自己的已有目录：

```powershell
Copy-Item config.example.json config.local.json
python configure_plugin.py --config "config.local.json" --projects-root "C:\work\projects"
```

3. 在支持本地插件的客户端导入该目录；或将生成的 `.mcp.json` 中 `stage-relay` 注册为 stdio MCP 服务。任选一种，勿重复注册。ZIP 内的空 `.mcp.json` 需要先经过上述配置。
4. 调用 `@stage-relay` 打开面板。在「模型与接口」填写地址与 API Key，读取接口模型列表，选择并保存要使用的模型。Windows 密钥由凭据管理器保存，不要求设置环境变量。

模型目录只表示接口声明支持哪些模型。开始正式任务前，可用「检查所选模型」验证：查看目录不请求生成；「试着回答一句」「试跑接力格式」会发起真实请求，可能收费。

## 使用流程

1. 在当前 Codex 对话说明任务并调用插件。Codex 先打开面板，在同一轮只读准备方案，不提前完成任务。
2. 在面板核对方案；需要调整时填写「给执行模型的补充条件」，然后点击「开始任务」。也可选择由独立规划模型准备方案。
3. 查看执行回答、文件改动和检查结果。完成后自行确认结束，或选择当前 Codex / 已配置模型审核。
4. 审核要求修改时，可自动交回原执行模型返修并交给同一审核方复审；也可只保留审核意见。自动返修会继续产生模型用量。

独立文件任务可自动创建带 Git 基线的工作目录。修改现有项目时，项目必须是已提交且干净的 Git 仓库根目录，运行记录应放在仓库外；不会自动 stash、提交或撤销你的改动。

「执行时分配子任务」默认关闭，可选择自动或指定分工。子 agent 复用执行模型；并行可能缩短大任务等待，也可能增加 token。

## 复用本机技能

**只为可识别的非 GPT 执行模型添加这层目录。GPT / Codex 路线不重复扫描或注入，继续沿用原生技能；无法辨认的模型别名也默认跳过。**

- 运行时识别本机用户技能、项目技能和已启用插件缓存中的技能，读取名称、简介和文件位置；不把使用者的技能复制进插件或发布包。
- 按任务提供少量相关技能元数据；完整目录保存在本地，模型需要时直接读取原 `SKILL.md` 和相对资源。推荐不是可用技能白名单。
- 面板区分推荐项与日志里有成功读取命令的项；未观察到读取不代表一定没使用，读取成功也不等于完成了全部步骤。
- 技能引用的浏览器、MCP、脚本环境仍须在执行端可用。目录提示依赖但不会创建工具、自动安装软件或授予权限。缺少必要能力时可向当前 Codex 求助。

目录根据本机配置和缓存推断，不保证等同于桌面对话的完整技能列表。禁用项会跳过；同一插件多份缓存按最新版本识别，不把旧缓存全部重复加入。别名与开关配置见[进阶说明](docs/advanced.md#技能发现与模型识别)。

## 上下文整理与求助

执行端可通过 `relay-context` 保存检查点，再用同一模型的新 CLI 上下文继续。原任务、方案、文件和累计用量保留；这不是原生 `/compact`，也不会退还已用 token。

遇到具体判断或缺少能力时，执行端可暂停并求助。当前 Codex 正在等待任务时能读到请求；对话已经结束时，在面板点「交给当前 Codex」，将复制的请求发回对话。网页不能后台唤醒已结束的对话，也可在面板直接填写答复后继续。

## 费用与验证

打开面板、查看日志、发现技能、复制求助和本地等待都不会请求模型生成。执行、独立模型规划、模型审核、格式修复及返修会产生供应商用量；部分接口的目录请求也可能按供应商规则收费。

插件通过复用已有方案、按需读取技能和本地调度减少重复上下文，不承诺固定节省比例，也不额外压低模型输出或正常执行额度。进度区显示累计请求与请求大小；字节数不是 token，费用缺失时显示未知。

项目验收命令在 `config.local.json` 的 `checks` 配置，例如：

```json
{"checks": {"unit": ["python", "-m", "unittest", "discover", "-s", "tests"]}}
```

未配置检查时会明确说明；执行模型自报完成不等于测试通过。问题旁的说明与审核入口提供核对对象和处理路径，审核确认解决的提醒会保留依据后关闭。

## 常见问题

| 情况 | 处理 |
| --- | --- |
| 接口无法连接、认证或模型失败 | 先用面板模型检查，核对网关是否启动、凭据、模型 ID 与 Responses 兼容性 |
| 任务超时 | 查看失败阶段和日志；正式模型阶段按连续无活动时间计时，相关设置见进阶配置 |
| 执行端没有当前对话的浏览器 | 可选视觉检查不阻塞交付；必要时通过求助或审核交回当前 Codex |
| 升级后工具或界面仍旧 | 重新连接插件并打开新版面板，避免使用旧会话的 MCP 连接 |
| 任务记录过多 | 在任务记录管理中多选或全选删除；运行中记录受保护，列表删除可撤销 |

## 本地演示与开发

```powershell
python demo.py
python -m unittest discover -s tests
python build_plugin.py
```

默认演示使用本地模拟模型，输出 `MOCK_NO_PAID_CALLS`。`--live` 才会请求真实模型。命令行使用、故障恢复、用量边界及开发验证见[进阶配置](docs/advanced.md)。
