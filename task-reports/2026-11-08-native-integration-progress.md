# Stage Relay 0.2 原生接入预览进度（整体未完成）

## 已完成的部分

DSH 已接通真实桌面应用中的原生 Agent，会话沿用原应用预设、工具、技能和插件环境。面板通过原生 `followup` / `steer` 送达任务和协作消息，没有直接调用模型 API，也没有自建替代执行器。

- 支持绑定同工作区原生会话，或让 DSH 创建新会话。
- 从原应用读取模型列表，只切换当前会话下一次请求，保留应用全局默认模型。
- 记录原生请求头中的实际模型、工具活动、执行错误和派发回执。
- 同一提供商和模型通道排队，避免测试中实际遇到的 429 并发限制。
- 交付记录已加入项目划分。

## 实际验证

1. 用户指定 `buddy/deepseek-v4.1-flash` 后，DSH 原生 Agent 使用 `subagent` 工具创建了真实子会话，回收 `17*23=391`，写入并读回 `native-evidence.json`，通过协作桥提交待核验结果。
2. 独立读取父、子原生会话日志中的请求头，两者实际模型均为 `antigravity-pool / buddy/deepseek-v4.1-flash`。这项证据来自原应用日志，不能只依赖 Agent 的自述。
3. 两个 DSH 原生会话完成真实议题回复；执行者写入 `collaboration.txt`，监督者独立读取并验收，指定汇总者提交最终说明。没有用预写回复代替真实 Agent。
4. 新版 exe 构建成功；使用打包的 `StageRelayBridge.exe` 运行 48 项测试，全部通过。DSH 配置测试还调用了其官方配置合成器，验证新增插件确实挂载，而非仅检查 YAML 语法。
5. 打包程序在隔离端口返回 `0.2.0-preview` 健康回执；独立浏览器截图检查成功，退出码为 0，截图为 `qa/stage-relay-v0.2.png`。DSH 原生窗口读取曾等待授权超时；真实执行验证随后通过原生插件和日志完成。

真实测试证据分别保存在 `qa/native-probe-20261108-190807/` 与 `qa/native-probe-collaboration-20261108-191819/`，这些目录含本机测试状态，已加入 Git 忽略，不包含在发布压缩包中。

## 尚未完成

- Codex 和 Antigravity 的原生自动唤醒与完整跨应用协作。它们目前仍是 MCP 协作信箱，界面明确提示此边界。本机 Codex 已运行服务的控制 socket 未能连接；没有用裸模型接口冒充接入。
- 项目结束、原生主/子会话自动归档、后台资源回收和定期垃圾清理。当前真实测试会停止测试工作并撤销临时插件接入，但创建的原生对话记录仍保留在 DSH；不能声称已经自动清理。
- 原应用所有第三方插件并未逐一验证，其他 DSH 版本兼容性也尚未验证。

## 新增清理要求

清理应成为项目生命周期的一部分：先保留交付、决定和审查依据，再停止项目拥有的工作，归档面板创建的原生会话，最后按资源登记清理临时文件。用户手动绑定的已有会话只解绑，多个项目共享的应用和插件保留。默认可恢复，并提供清单、日志、失败重试与崩溃后恢复；不会按进程名批量杀应用或扫描硬盘猜测垃圾。

这些规则已加入 `PRODUCT_REQUIREMENTS.md`，还没有伪装成当前预览包已有功能。
