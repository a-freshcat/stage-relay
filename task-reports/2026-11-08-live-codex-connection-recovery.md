# 真实 Codex 接入与重开恢复修复

## 结果

当前真实面板已从实际运行的 0.3.2 切换至 0.3.6，沿用原数据目录。按用户选择新建并绑定独立 Codex 审核会话，保留被占用的旧会话和原成果。最终实际执行面板正常关闭和重新打开，同一个独立审核会话恢复成功、无占用错误；Codex 与 DSH 均在线，项目仍暂停。

## 查到与修复的问题

- 最初运行的仍是旧版 0.3.2，因此此前交付的新占用提示尚未生效。更新后确认：原生连接已连通，真正阻塞的是绑定的旧会话写入权。
- 原生在线状态和 MCP 工具最后调用时间此前混用，导致已连接但尚未发起任务的成员仍显示“等待应用确认”。现按真实原生心跳显示在线。
- 旧额度错误此前像当前接入故障一样展示，现标为可展开的“上次执行记录”。历史额度记录不能证明当前额度是否可用。
- 暂停状态曾连创建工作会话也一起阻止。现在只允许准备连接、模型管理等控制操作，继续禁止任务执行；替换绑定要用户明确选择。
- 创建独立会话成功后，旧会话保留，未送达旧会话的请求取消，不重放已送达或不确定请求。若创建过程中用户更换了绑定，迟到的新会话不覆盖用户选择。
- 新建空会话在登记可恢复绑定前，通过原生 thread/name/set 持久化名称；正常退出前对本连接实际拥有的会话调用 thread/unsubscribe，再关闭原生连接。不解除订阅未成功接管的会话，不删除写入锁。
