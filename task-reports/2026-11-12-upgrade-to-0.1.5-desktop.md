## 一、故障的真实原因（已复核）

用户双击 v0.1.5 失败。`desktop.log` 实际内容：

```
2026-11-12 13:06:18,372 ERROR Desktop startup failed
  File "desktop.py", line 81, in main            -> PanelServer.__init__ 绑定 4318
  ...
OSError: [WinError 10048] 通常每个套接字地址...只允许使用一次。

During handling of the above exception, another exception occurred:
  File "desktop.py", line 88, in main
RuntimeError: 旧版本地服务正在运行，请先关闭旧版再启动新版。
```

占用 4318 的实例身份（实测）：

```
pid     27268
进程    C:\Python314\python.exe
命令行  app.py --port 4318 --data-dir "...\Stage Relay\data"
version 0.1.4
```

**这个进程是我在 #805 按批准方案启动的部署实例。** 用户后续通过面板"重启 Web"并没有替换这个后台——它至今仍是 0.1.4，所以 0.1.5 桌面程序一启动就撞端口。

这不是 WebView2 缺失，`catch` 里那句统一提示是误导（已在源码修复）。

## 四、切换步骤（待授权）

### 4.1 执行前检查

```
1) 确认占用者仍是 pid 27268 且仍是 --port 4318 --data-dir 原路径
   （PID 变了就停下报告，不按旧 PID 盲停）
2) GET /api/health 记录：pid / version / data_dir
3) 全成员在途判定：
   SELECT project,agent,id,status FROM native_jobs
    WHERE status IN ('queued','leased','uncertain');
   - 有 leased / uncertain  -> 不切换，报告后等指示
   - 只有 queued            -> 安全（库里状态，新版启动后 poll 会重新领取）
```

当前快照（2026-11-12 13:2x）：

```
in-flight   deepseek  delivery_92bee68b7f4c  queued      <- 仅 queued
integrity   ok
events      858
jobs        484
bindings    4
heartbeat   deepseek 1.2s / antigravity 0.5s / codex 0.3s   三者均活跃
```

### 4.2 一致备份

```python
s = sqlite3.connect(f'file:{src}?mode=ro', uri=True)   # 只读打开
d = sqlite3.connect(dst); s.backup(d)                  # 在线一致性快照
```

```
落盘  <data-dir>\..\workspace.sqlite3.before-0.1.5-desktop.bak
校验  PRAGMA integrity_check -> ok；记录 events / jobs / bindings 行数
同时  connection-ownership.json.before-0.1.5-desktop.bak
```

不用文件复制：WAL 下可能拿到撕裂的库。

### 4.3 停止旧后台（仅这一个 PID）

```
确认 pid 仍是 27268 -> Stop-Process -Id 27268
确认 4318 释放
```

不关闭 Antigravity、不关闭 DSH 应用、不动其它项目。

### 4.4 启动已发布桌面程序

```
<repo>\release\StageRelay-0.1.5\Stage Relay\Stage Relay.exe
  --port 4318 --data-dir "<原 data-dir>"
```

启动后核对：

```
GET /api/health  期望 version = 0.1.5
                 期望 data_dir = 原路径
                 期望 pid 为新 PID
                 期望 antigravity.online = true
四条绑定保持不变
```

### 4.5 失败处置

```
日志保留  <data-dir>\desktop.log（追加写入，不清空）
若启动失败：
  1) 保留 desktop.log 原文
  2) 恢复原后台（可回退到 0.1.4 源码目录 + 同一 --port/--data-dir）
  3) 报告实际错误与两个版本各自的 health
不自动覆盖数据库
```
