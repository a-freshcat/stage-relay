# 审核负责人切换与 Codex 占用保护

## 结果

已实现并打包为 0.3.4。连接等待不会持有面板状态锁；同一成员的并发连接请求合并，已有连接复用。单个原生会话恢复失败只登记为待重连，不使其他会话全部断开。正在被其他连接写入的会话不会被强行接管。

切换审核负责人保留板块和检查依据，停止给旧负责人派发待送达审核通知。旧负责人的迟到结果保存为参考，不改变验收状态；审核轮次防止 A → B → A 后旧结果误用。用户界面提供审核等待连接、中文占用说明、技术详情、重试和此前审核意见入口。切换模型使用已拥有的会话下次 turn/start 参数，不为此重复 thread/resume。

## 实际验证

- 全量 Python 回归共 84 项，结果 OK（其中 1 项需显式开启真实 Codex，已跳过）。最后补充的旧监督通知过滤又通过 6 项交接检查与 15 项 runtime 检查。
- UI 探针 18 项通过，覆盖中文输入法保护、审核等待、中文占用提示和重试入口；这是脚本渲染检查，不是实际浏览器视觉检查。
- 新打包 exe 的隔离实例实际验证：创建成果、切换审核员、旧结果仅作参考、新审核通过，原成果保留。该测试使用 qa/release-034-data 和假应用配置，没有接入真实 Agent。
- 打包产物：release/StageRelay-0.3.4-codex-dsh-20261108-231209/Stage Relay/Stage Relay.exe。

## 升级与边界

没有重启当前真实面板、恢复暂停任务或操作用户正在使用的 Codex 会话。截图中实际占用者尚未确认，本轮验证的是占用发生时的容错与审核交接，不宣称清除了该真实占用。

先关闭旧面板，再打开新 exe；沿用旧数据目录。由于审核工具新增 review_epoch，旧版桥接程序需要在面板中通过「更新接入配置」更新一次，并让原应用加载新工具。新版本不会继续复用旧版冻结桥接程序。后续只切换审核负责人时复用正常连接，不重复要求授权。独占占用仍在时可继续使用面板、换负责人或显式绑定其他工作会话；不能自动抢占或重放任务。
